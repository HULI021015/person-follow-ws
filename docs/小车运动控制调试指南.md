# 小车运动控制调试指南

适用：Ubuntu 22.04 / ROS 2 Humble / CAN115 四轮差速底盘  
原则：先架空、再落地；先停车、再直行、最后转向；任何异常立即物理急停。

## 1. 调试前安全检查

- 车轮完全离地，支架稳定，周围没有衣物、线缆和人员。
- 物理急停、总电源开关可在一秒内触达。
- 电池电压正常，前后驱动器无报警。
- CAN115 网线连接正确，电脑网口和底盘处于同一网段。
- 关闭所有可能控制小车的软件，只运行一个 `chassis_node`。
- 初次调试把 `max_linear_speed` 和发布测试值都设得保守。

## 2. 通信检查（不会让车运动）

```bash
source /opt/ros/humble/setup.bash
source ~/person_follow_ws/install/setup.bash
ping -c 2 192.168.0.7
timeout 2 bash -c '</dev/tcp/192.168.0.7/5578' && echo CAN_TCP_OK
```

只有 `CAN_TCP_OK` 后才启动驱动：

```bash
ros2 run vehicle_bringup chassis_node --ros-args \
  --params-file ~/person_follow_ws/src/vehicle_bringup/config/chassis.yaml
```

正常日志包含“已连接 CAN115 192.168.0.7:5578”。若日志提示自动重试：

1. 确认没有第二个 TCP 客户端占用 CAN115。
2. 检查 Windows/WSL 防火墙和网卡路由。
3. `ip route get 192.168.0.7` 检查实际出口。
4. 暂停调试，不要绕过连接检查发送指令。

## 3. ROS 话题与看门狗检查

另开终端：

```bash
source /opt/ros/humble/setup.bash
source ~/person_follow_ws/install/setup.bash
ros2 node list
ros2 topic info /cmd_vel -v
ros2 topic echo /odom
```

期望看到 `/chassis_node` 订阅 `/cmd_vel`。不发送命令时车轮必须停止。

发送一次零速：

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.0}}'
```

然后持续发一个仍为零的命令，验证链路：

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.0}}'
```

按 `Ctrl+C` 后车轮必须保持停止。

## 4. 架空低速方向测试

所有运动命令都使用 `timeout` 限时，避免终端失控后持续运动。

### 4.1 前进

```bash
timeout 0.5 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.05}, angular: {z: 0.0}}'
~/person_follow_ws/scripts/stop_robot.sh
```

从车尾向车头看，四个轮子都应产生让车辆向前的趋势。任何一个轮方向相反都立即停车。

### 4.2 后退

```bash
timeout 0.5 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: -0.05}, angular: {z: 0.0}}'
~/person_follow_ws/scripts/stop_robot.sh
```

四轮方向应与前进完全相反。

### 4.3 左转和右转

ROS 标准：`angular.z > 0` 左转，`angular.z < 0` 右转。

```bash
# 左转
timeout 0.5 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.15}}'
~/person_follow_ws/scripts/stop_robot.sh

# 右转
timeout 0.5 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: -0.15}}'
~/person_follow_ws/scripts/stop_robot.sh
```

左转时左轮向后、右轮向前；右转相反。

## 5. 方向错误的处理

不要在 `person_follower` 中通过改转向符号掩盖底盘接线或 SDK 配置问题。先保证 `/cmd_vel` 符合 ROS 约定。

电机符号位于 `src/yk_can_sdk/yk_can_sdk/config.py` 的 `VehicleConfig`：

- `front_motor1_sign`：前驱动器 1 号电机
- `front_motor2_sign`：前驱动器 2 号电机
- `rear_motor1_sign`：后驱动器 1 号电机
- `rear_motor2_sign`：后驱动器 2 号电机

参考车默认 `motor1=+1`、`motor2=-1`。只反转确认错误的电机符号，每次只改一项，重新构建并再次架空测试。若整车前后方向全部颠倒，优先检查电机编号和车头定义，不要同时随意翻转多个层级。

## 6. 看门狗实测

架空状态连续发送低速 2 秒，然后中断发布：

```bash
timeout 2 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.05}, angular: {z: 0.0}}'
```

预期：停止发布后 0.5 秒内车轮停止，底盘节点记录 `/cmd_vel 超时，已停车`。如果未停，立即物理急停并排查节点是否是当前源码构建、是否有其他 publisher 仍在发送。

查看所有发布者：

```bash
ros2 topic info /cmd_vel -v
```

联合运行时正常只有 `person_follower_node` 向 `/cmd_vel` 发布。

## 7. 落地低速标定

选择至少 3 m × 3 m 的平整空地，地面贴起止线。保持 `max_forward_speed <= 0.12`、`max_angular_speed <= 0.30` 开始。

### 7.1 直线速度

以固定 `linear.x=0.10 m/s` 发布 3 秒，理论位移 0.30 m，测实际位移。多次重复取平均：

```text
新 max_linear_speed = 当前 max_linear_speed × 实际位移 / 指令积分位移
```

参考项目的 `max_linear_speed=1.257 m/s` 来自原车实测，但轮胎、载荷、电压和地面变化都会影响结果。

### 7.2 原地角速度

以低角速度转固定时间，测实际转角：

```text
新 max_angular_speed = 当前 max_angular_speed × 实际转角 / 指令积分转角
```

参考项目值为 `1.67 rad/s`。如低出力有死区，应先确认驱动模式，再适当提高最低测试命令，禁止一次跳到高速。

### 7.3 里程计限制

当前 `/odom` 由已发送命令积分，并没有读取实际编码器速度。它可用于查看控制趋势，不能作为精确标定真值；标定必须用卷尺、角度标线或外部测量。

## 8. 视觉控制方向检查

底盘仍架空，先用 NetSDK 相机测试确认没有视频历史队列：

```bash
source ~/person_follow_ws/scripts/netsdk_env.sh
ros2 run person_follower camera_latency_test --duration 10 --stream extra
```

再启动联合节点。被跟随者缓慢移动：

| 人的位置/距离 | `/cmd_vel` 预期 |
|---|---|
| 画面中央且较远 | `linear.x > 0`，`angular.z ≈ 0` |
| 画面右侧 | `angular.z < 0`（右转） |
| 画面左侧 | `angular.z > 0`（左转） |
| 达到设定距离 | `linear.x ≈ 0` |
| 人消失或画面断开 | 立即为零 |

命令观察：

```bash
ros2 topic echo /cmd_vel
```

联合节点日志中的“当前帧龄”是解码回调到 YOLO 推理完成的时间。超过 `max_control_latency`（默认 0.50 s）时必须看到 `/cmd_vel` 归零；断开相机后超过 `frame_timeout`（默认 0.70 s）也必须归零。摄像机 OSD 时间落后但人物动作实时，表示摄像机时钟未校准，不应误判为视频缓存。

如果左右相反，先确认相机画面是否水平镜像；无镜像时，检查 `controller.py` 中图像误差到 ROS 角速度的负号。底盘方向已经按第 4 节确认后，才允许在视觉层处理镜像问题。

## 9. 跟随调参顺序

1. `target_width_ratio`：先决定停车距离。
2. `max_forward_speed` / `max_angular_speed`：先限制风险上限。
3. `linear_gain`：控制追近积极程度。
4. `angular_gain`：控制追踪左右偏差的速度。
5. 两个 deadzone：消除距离和方向小范围抖动。
6. `smoothing_alpha`：最后改善动作平顺性。

现象与处理：

| 现象 | 优先调整 |
|---|---|
| 前后反复振荡 | 增大 `width_deadzone_ratio`，减小 `linear_gain` |
| 左右蛇形 | 减小 `angular_gain`，减小 `smoothing_alpha`，增大中心死区 |
| 转弯时冲得太快 | 降低 `max_forward_speed` |
| 跟随反应太慢 | 在帧率足够前提下增大 gain 或 alpha |
| 目标切换频繁 | 增大 `lost_limit_frames`，改善相机视野 |
| 人过近仍前进 | 重新标定 `target_width_ratio`，检查框宽是否稳定 |

## 10. 故障处置

### 小车突然冲转

立即物理急停并断电。检查 `/cmd_vel` 发布者、方向符号、速度上限及是否运行了多个节点。不要在车轮落地状态下直接复现。

### 停停走走

查看视觉实际 FPS 和帧龄。SDK 看门狗为 0.25 秒，控制更新低于 4 Hz 会主动停车。降低 `image_size`、使用 `camera_stream: extra` 辅码流或启用 GPU。

### CAN 发送失败后不能恢复

停止联合节点，确认唯一 TCP 客户端，重新启动 `chassis_node`。SDK 故障急停可能是锁存的，必须先排除驱动器故障，不能仅靠重复发送运动命令清除。

### 退出后仍运动

先物理急停。确认 `ros2 topic info /cmd_vel -v` 没有其他发布者；再检查是否运行的是旧工作区环境。使用 `which ros2`、`ros2 pkg prefix vehicle_bringup` 验证来源。

## 11. 调试完成验收表

- [ ] WSL 到相机与 CAN115 端口均可达。
- [ ] `camera_latency_test` 能持续解码，PlaySDK 输入丢弃数无持续增长。
- [ ] 快照动作实时；若仅 OSD 时间有差值，已在摄像机中完成 NTP/时区校准。
- [ ] 仅一个底盘控制 TCP 客户端。
- [ ] 零速命令不产生轮动。
- [ ] 四轮前后方向一致。
- [ ] 正角速度左转、负角速度右转。
- [ ] 停止 `/cmd_vel` 后 0.5 秒内自动停车。
- [ ] 目标丢失、相机中断、节点退出均停车。
- [ ] 跟随距离已现场标定。
- [ ] 最大线/角速度从低值逐步验证。
- [ ] 物理急停已实际演练。
