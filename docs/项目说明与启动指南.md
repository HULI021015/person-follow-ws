# ROS 2 人员跟随小车：项目说明与启动指南

版本：1.1  
目标系统：Ubuntu 22.04 / ROS 2 Humble  
工作区：`/home/zheng/person_follow_ws`

## 1. 项目目标与依据

本项目实现：大华网络摄像机识别到人后，小车自动转向目标、靠近目标，并以人体检测框宽作为距离代理量保持预设距离；目标消失、画面中断、ROS 指令超时或进程退出时，底盘自动停车。

实现依据有两部分：

1. `track.zip`：沿用大华相机、YOLOv8 的 COCO `person` 类、BoT-SORT 多目标跟踪、最大框优先锁定目标、框宽控制距离的算法结构。
2. `lidar_patrol_ws.rar`：沿用相同小车的 YK CAN SDK、CAN115 地址 `192.168.0.7:5578`、四轮差速符号配置、`/cmd_vel` 到底盘的控制链路以及标定速度上限。

原视觉工程没有实际底盘发送实现，且引用的模型绝对路径和自定义 BoT-SORT YAML 未包含在压缩包中。本项目用 Ultralytics 自带 `botsort.yaml`，模型默认使用同名 `yolov8n.pt`；如果有原始 `.pt` 或 `botsort_stable.yaml`，可通过参数直接替换。

## 2. 系统结构

```text
大华摄像机 (NetSDK 实时码流回调)
        │
        ▼
PlaySDK 实时解码（缓存 1 帧）
        │  只保留最新帧
        ▼
person_follower_node
  YOLOv8 person 检测
  + BoT-SORT ID 跟踪
  + 目标锁定/距离控制/安全停车
        │  geometry_msgs/Twist
        ▼  /cmd_vel
chassis_node
  物理速度限幅 + ROS 看门狗
        │
        ▼
yk_can_sdk
  加减速斜坡 + SDK 看门狗 + 故障急停
        │ TCP 192.168.0.7:5578
        ▼
CAN115 → 前后电机驱动器 → 四轮差速底盘
```

## 4. 硬件和网络前提

当前电脑在 WSL 中已实测可访问：

- 底盘 CAN115：`192.168.0.7:5578`
- 大华 NetSDK：`192.168.1.21:37777`

不要让其他程序同时连接 CAN115；该网关通常只允许一个活动 TCP 客户端。相机和底盘若改过 IP，请同步修改 YAML。

检查命令：

```bash
timeout 2 bash -c '</dev/tcp/192.168.0.7/5578' && echo CAN_OK
timeout 2 bash -c '</dev/tcp/192.168.1.21/37777' && echo CAMERA_SDK_OK
```

本机当前实测为 WSL NAT：Windows 可连接 `192.168.1.21:37777`，但 WSL 不能直接连接。如果 `CAMERA_SDK_OK` 未出现，可使用项目自带的 TCP 转发。先在 WSL 查 Windows 网关：

```bash
grep nameserver /etc/resolv.conf
```

假设输出为 `172.26.16.1`，在 Windows PowerShell 保持运行：

```powershell
cd 'C:\Users\zheng\Documents\ChatGPT\数智平台小车'
PowerShell -ExecutionPolicy Bypass -File scripts\start_camera_relay_windows.ps1
```

该脚本自动读取 WSL 网关并保持前台运行。然后在 WSL 直接执行 `./scripts/start_follow.sh`；启动脚本发现相机不能直连时，会自动改用网关的 37778 转发。也可以手动指定：

```bash
export DAHUA_IP='172.26.16.1'
export DAHUA_PORT='37778'
```

转发脚本只绑定指定的 WSL 虚拟网卡地址，不要改为 `0.0.0.0`，否则可能把摄像机 SDK 端口暴露给其他网络。WSL 重启后网关地址可能变化，需要重新查询。

## 5. 安装依赖

### 5.1 ROS 2 基础环境

本机已有 `/opt/ros/humble`。每个新终端先执行：

```bash
source /opt/ros/humble/setup.bash
```

如在另一台全新 Ubuntu 22.04 上部署，应先按 ROS 2 Humble 官方方法安装 `ros-humble-desktop` 和 `python3-colcon-common-extensions`。

### 5.2 项目依赖

```bash
cd ~/person_follow_ws
chmod +x scripts/*.sh
./scripts/install_dependencies.sh
```

关键依赖：

- ROS：`rclpy`、`geometry_msgs`、`nav_msgs`、`tf2_ros`、`launch_ros`
- 图像：OpenCV、NumPy
- 识别：Ultralytics YOLO、PyTorch
- 取流：大华 NetSDK 2.0.0.1、PlaySDK（由用户提供的 Linux x86_64 wheel 安装）
- 调试：`teleop_twist_keyboard`、pytest

脚本会安装 `vendor/NetSDK-2.0.0.1-py3-none-linux_x86_64.whl`，并验证 NetSDK 与 PlaySDK 动态库。若机器已经有 PyTorch，脚本不会替换它；若没有，则安装 CPU 版。`device: auto` 会在 `torch.cuda.is_available()` 为真时自动使用 `cuda:0`。

验证：


## 7. 首次启动前配置

主配置：`src/person_follower/config/follower.yaml`。

按当前部署要求，相机密码已作为 `follower.yaml` 的默认值，因此可直接启动。若密码变化，推荐在启动前用环境变量覆盖，避免继续修改源码：

```bash
export DAHUA_PASSWORD='实际相机密码'
```

环境变量优先于 YAML。默认 `camera_stream: extra` 使用辅码流；需要更高分辨率时可改为 `main`，但推理时延和网络负载会增加。当前工作区含明文默认密码，复制或共享项目时应先删除或替换该值。

`DAHUA_IP`、`DAHUA_PORT`、`DAHUA_USER`、`DAHUA_PASSWORD` 环境变量优先于 YAML，便于 WSL NAT 转发且不会把凭据写入项目。

如果已有原模型：

```bash
export YOLO_MODEL='/home/zheng/models/yolov8n.pt'
```

模型文件不在两个压缩包内；首次使用 `yolov8n.pt` 时 Ultralytics 可能联网下载。离线部署请提前把模型放到本机并写绝对路径。

## 8. 分阶段启动

### 8.1 先测 NetSDK 取流延迟（不会控制底盘）

```bash
cd ~/person_follow_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
source scripts/netsdk_env.sh
ros2 run person_follower camera_latency_test --duration 10 --stream extra \
  --snapshot /tmp/dahua_latest.jpg
```

`RESULT` 会报告实际接收 FPS、回调后帧龄平均值/P95/最大值，以及 PlaySDK 输入丢弃数。这里的“帧龄”测量的是帧进入 Python 后到读取最新帧的排队时间；应接近毫秒级。它不能直接测量摄像机编码、网络传输之前的时间。

检查快照右上角的摄像机 OSD 时间：如果动作已实时但 OSD 始终比系统钟慢十几秒，原因是摄像机自身时间/NTP 配置，而不是取流缓存，应在摄像机管理页面校时。如果挥手动作也晚十几秒，才是端到端视频延迟。

### 8.2 只验证相机和识别，不启动底盘

先保证没有其他节点向 `/cmd_vel` 发运动指令：

```bash
cd ~/person_follow_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
source scripts/netsdk_env.sh
ros2 launch person_follower follow.launch.py start_chassis:=false show_window:=true
```

若 WSLg 图窗不可用，将 `show_window` 保持 `false`，同时另开终端观察控制输出：

```bash
ros2 topic echo /cmd_vel
```

预期：无人时全零；人在画面右侧时 `angular.z < 0`；人在左侧时 `angular.z > 0`；人较远且居中时 `linear.x > 0`。

日志每秒输出处理 FPS、YOLO 推理耗时和当前帧龄。节点只处理新帧；推理期间到达的旧帧会被新帧覆盖，不会积成十几秒的历史队列。处理后帧龄超过 `max_control_latency`（默认 0.50 s）或画面超过 `frame_timeout`（默认 0.70 s）未更新时，节点发布零速。

### 8.3 只启动底盘驱动

先架空车轮，然后：

```bash
ros2 run vehicle_bringup chassis_node --ros-args \
  --params-file ~/person_follow_ws/src/vehicle_bringup/config/chassis.yaml
```

具体低速方向测试见《小车运动控制调试指南》。方向未确认前禁止联合跟随。

### 8.4 联合跟随

把小车放在宽阔平整区域，操作者手持物理急停：

```bash
cd ~/person_follow_ws
export DAHUA_PASSWORD='实际相机密码'
./scripts/start_follow.sh
```

紧急软件停车（另一终端）：

```bash
~/person_follow_ws/scripts/stop_robot.sh
```

`Ctrl+C` 会触发视觉节点和底盘节点的零速停车，但物理急停仍是最终安全手段。

## 9. 距离与控制参数

人体框宽只是距离代理，不是米制深度。`target_width_ratio` 表示理想距离处“人体框宽 / 图像宽度”。默认 `0.385` 来自参考值 `740 px / 1920 px`。

标定步骤：

1. 把被跟随者站在期望距离，例如 1.2 m。
2. 只运行视觉节点并查看框宽；用 `框宽 / 图像宽度` 得到比例。
3. 把该值写入 `target_width_ratio`。
4. 从 `max_forward_speed: 0.12`、`max_angular_speed: 0.30` 开始实车试验。
5. 稳定后逐步增加速度；一次只改一个参数。

主要参数：

| 参数 | 含义 | 默认值 |
|---|---|---:|
| `target_width_ratio` | 理想距离的人框宽占比 | 0.385 |
| `linear_gain` | 距离误差到线速度的比例 | 0.65 |
| `angular_gain` | 横向误差到角速度的比例 | 1.10 |
| `width_deadzone_ratio` | 距离死区，减小前后抖动 | 0.10 |
| `center_deadzone_ratio` | 画面中心死区，减小左右摆动 | 0.05 |
| `max_forward_speed` | 最大前进速度 m/s | 0.35 |
| `max_angular_speed` | 最大角速度 rad/s | 0.80 |
| `allow_reverse` | 人过近时是否后退 | false |
| `smoothing_alpha` | 控制低通系数，越小越平滑 | 0.35 |
| `lost_limit_frames` | 换目标前容忍丢失帧数 | 15 |
| `camera_stream` | `extra` 辅码流或 `main` 主码流 | extra |
| `control_rate` | 尝试读取和处理新帧的频率 Hz | 20.0 |
| `frame_timeout` | 无新解码帧时的停车阈值 s | 0.70 |
| `max_control_latency` | 推理完成后允许的最大帧龄 s | 0.50 |

默认禁止倒车，因为后方没有视觉保护。目标一旦在当前帧消失，节点立即发布零速；丢失帧阈值只决定何时允许切换到另一个人的 ID。

## 10. 安全机制

1. 视觉层：无目标立即零速；相机超时零速；节点退出零速。
2. ROS 底盘层：`/cmd_vel` 超过 0.5 s 未更新，调用 SDK `stop()`。
3. SDK 层：命令看门狗、加减速斜坡、驱动故障急停、连接关闭前零速连发。
4. 默认线速度和角速度双重限幅。
5. 目标大幅偏离中心时自动降低前进速度，减少转弯切角。

合规注意：摄像机画面涉及个人信息，应限定采集范围和保存权限；本项目默认不录像、不保存帧。

## 11. 常见问题

### 找不到 `ultralytics` 或 `torch`

运行 `./scripts/install_dependencies.sh`；若网络受限，把可用的 wheel 与模型文件离线拷入 WSL。

### 相机端口通但 NetSDK 登录失败

检查账号密码、37777 端口、通道号以及摄像机是否允许 SDK 登录。确认安装的是 Linux x86_64 wheel，而不是 `win_amd64.whl`。

### 提示 `动态库加载失败` 或没有 `play_sdk`

执行 `source ~/person_follow_ws/scripts/netsdk_env.sh`。`libplay.so` 依赖同目录的 `libRenderEngine.so` 等库，只安装 wheel 而没有设置 `LD_LIBRARY_PATH` 会导致 PlaySDK 加载失败。`start_follow.sh` 和联合 launch 已自动设置该路径。

### 首帧延迟或跟随滞后

使用 `camera_stream: extra`，降低 `image_size`，优先使用 CUDA。观察日志中的“当前帧龄”；超出 500 ms 会主动停车。控制必须稳定在至少 4 Hz 以上，否则底盘 SDK 看门狗会主动停车。

### 底盘端口被占用

关闭参考工程、测试脚本或第二个 chassis 节点。一次只保留一个 CAN115 TCP 客户端。

### WSL 网络模式变化后无法直连底盘

先测试 `192.168.0.7:5578`。如确实只能由 Windows 访问，可在 Windows 运行 `scripts/forward_5578_windows.py`，然后把 `can_host` 改为 WSL 默认网关地址；不要盲目使用 `127.0.0.1`，NAT 模式下它指向 WSL 自身。

## 12. 已知边界

- 单目框宽受人的体型、姿态和遮挡影响，保持的是视觉比例，不是精确米制距离。
- 默认选择面积最大的人员并锁定 BoT-SORT ID；多人交叉或完全遮挡时可能换人。
- OpenCV 仍用于 IYUV→BGR 转换、画框和窗口显示，但已完全移除 OpenCV/FFmpeg 的 RTSP 取流路径。
- 首次启动会先用空白帧预热 YOLO/CUDA；预热期间不产生运动指令，避免第一张实景帧因模型初始化而延迟数秒。
- 本项目不包含激光避障。首次场地必须清空障碍，并保持人工急停监护。
- `/odom` 为指令积分估计，并非轮速闭环真值；如需导航定位，应接入真实编码器里程计。

## 13. 本机验证结果

2026 年 9 月 4 日在本机 WSL Ubuntu 22.04 完成以下验证，底盘节点未启动：

- 大华 Linux NetSDK 2.0.0.1 和 PlaySDK 动态库均加载成功，相机登录成功。
- 12 秒纯取流测试收到 319 帧，观测帧率 26.22 FPS，码流报告 25 FPS。
- Python 最新帧队列的平均帧龄 1.31 ms，P95 为 2.20 ms，最大 17.23 ms，PlaySDK 输入丢弃为 0。
- YOLOv8n 和 BoT-SORT 使用 `cuda:0`，预热后稳定约 20 FPS，单帧推理约 29–43 ms，推理完成后的帧龄约 33–60 ms。
- 相机快照 OSD 与保存时刻约差 2 秒，没有复现原 OpenCV RTSP 链路的十几到二十秒积压。
- 3 个 ROS 2 包编译成功，控制器 5 项单元测试通过，`Ctrl+C` 后 NetSDK 与 PlaySDK 能干净退出。

这些结果证明视觉链路已达到实时控制所需的更新速度。实车方向、制动距离和最大安全速度仍须按《小车运动控制调试指南》在架空和低速条件下逐项验收。
